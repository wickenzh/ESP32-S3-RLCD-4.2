# WeatherClock 用户使用说明

聚合时钟日期区显示公历日号及农历月份、农历日；个位日号不补零。升级到八页后保留原页面配置并追加新页，无需恢复出厂。

v1.6.0 新增“聚合时钟”：上方显示时分秒，下方显示当天天气、日期与农历日、本地温湿度。默认排在最后，可在“设置 → 显示 → 页面开关/页面顺序”关闭或排序。天气与其他天气页共用缓存和整点同步；本地温湿度沿用白天1分钟、夜间2分钟采样。离线模式下此联网页面不可开启。页面灰底采用固定黑白点阵显示。

网页版上位机：[点击使用](https://wickenzh.github.io/ESP32-S3-RLCD-4.2/)。固件与上位机源码已统一放入同一仓库的 `RLCD_CLOCK/` 和 `host_web/`。旧站仍保留；本次仓库迁移不需要重新刷机或清除设备配置。

本文档面向 WeatherClock 的日常使用者，介绍首次开机、八个工作页面、按键、联网与离线配置、声音提醒、小智 AI、OTA 更新、DIY 图片资源和常见故障处理。

> **重要升级提示**：`v1.5.x` 使用新的 Flash 分区表。设备如果仍是 `v1.4.59` 或更早版本，首次升级到 `v1.5.x` 必须通过串口完整刷写 merged 固件或完整烧录包。仅刷 App bin 或直接 OTA 不能更新分区表。

> **v1.5.29 天气配置提示**：和风天气正在逐步停止旧公共 API 域名。升级到 `v1.5.29` 后必须重新进入配网页，填写和风天气控制台“设置 → API Host”中显示的账号专属域名；不补填时天气、预警、预报和空气质量无法更新。离线模式不需要填写。

## 1. 快速开始

1. 给设备上电，等待启动动画完成。
2. 首次使用时，用手机或电脑连接以 `WeatherClock-` 开头的热点。
3. 系统通常会自动打开配网页；如果没有弹出，请访问 `http://192.168.4.1/`。
4. 选择联网使用或离线使用：
   - 联网使用：填写 Wi-Fi 名称、Wi-Fi 密码、和风天气 API 密钥和账号专属 API Host。
   - 离线使用：不填写 Wi-Fi，只填写离线日期和时间。
5. 配置完成后，设备进入页面顺序中排在第一位的已启用页面。

设备日常使用只需要两个按键：

- **BOOT 短按**：在工作状态下切换到下一个已启用页面；在设置页中确认。
- **KEY 短按**：进入设置页；进入设置后移动选择项。
- **KEY 长按**：在设置二级菜单返回一级菜单；在一级菜单退出设置页。
- **任意按键**：闹钟或番茄钟完成提示正在播放时，停止本次提示音，并消费该次按键，不再继续执行切页或设置操作。

按键唤醒、闹钟、番茄钟和界面刷新在内部使用线程安全的任务通知；操作方式和响应规则不变，长时间运行或跨核心通知不再依赖未同步的任务句柄。

设置页无操作约 30 秒后会自动返回工作页面。页面顺序设置中的正常按键操作会重新开始超时计时。

设置页空闲时会等待按键、同步结果或 OTA 状态通知，不再持续轮询屏幕。反馈提示消失、手动同步超时和 30 秒自动返回仍会在原定时间触发，操作方式与响应速度不变。

关于本机或检查更新页面接近自动返回时间时，如果 OTA 正在更新页面状态或延长提示时间，设备会继续显示最新状态，不会被上一轮超时判断提前关闭。30 秒自动返回和长按返回操作不变。

在所有页面中，只要两个按键均已松开且没有正在跟踪的按压，按键任务就会等待 GPIO 边沿唤醒。设置、关于本机、网络检测和配网页也不再周期检查松开的按键；按下边沿会立即唤醒任务，再按原规则执行防抖、短按和长按。后台充电、联网、播放音频或执行 OTA 不影响该行为。

按键引脚和不同工作状态下的轮询回退参数现由输入模块统一维护；本次内部整理不改变按键引脚、防抖、长按阈值、Light Sleep 唤醒、响应速度或页面操作。

## 2. 顶部状态与全天进度

工作页会根据页面内容显示日期、星期、电池、Wi-Fi、声音提醒、闹钟和本地温湿度等状态。

- **Wi-Fi 图标**：Wi-Fi 射频开启时显示，关闭后隐藏；连接或同步期间也会显示，可用于判断设备当前是否正在使用无线网络。
- 如果系统暂时无法取得联网所需的唤醒资源，本次同步会安全失败或稍后重试，不会强行打开 Wi-Fi；可等待片刻后重新操作。
- Wi-Fi 名称、密码、天气 API Key 和账号专属 API Host 会作为一组完整配置生效；系统暂时忙碌时会继续使用上一组完整配置，不会混用新旧字段。
- 重复提交完全相同的联网配置不会重复写入设备存储；配网完成后的连接、天气同步和页面显示方式不变。
- 联网和音频会分别维护可嵌套的唤醒资源；某一步初始化失败时会回收本轮已经取得的资源，不会因为一次失败长期阻止设备进入原有省电状态。
- 开机同步或 OTA 偶遇 Wi-Fi 驱动重新配置失败时，设备也会登记射频关闭并在其它联网所有者结束后补处理，避免状态栏 Wi-Fi 图标和高功耗状态长期残留；正常联网与更新操作不变。
- 启动联网的最终提示仍会短暂保留，但设备会先释放 Wi-Fi 和对应唤醒锁，再完成这段显示停留；提示内容和开机顺序不变，只减少无必要的启动高功耗时间。
- 开机自动补拉天气或每日文字时，如果内部连续内存暂时不足，设备会保留任务，前几次约按 10、20、40、60 秒逐步等待，之后最多每分钟检查一次，避免长时间无数据时持续唤醒设备。设置页手动同步、配网验证和进入对应页面后的按需同步不受这项后台延期规则影响。
- 天气、预警、预报和空气质量会作为一致快照更新；预警、预报或空气质量接口暂时失败时，仅在定位未变化的情况下继续显示上一份有效数据。切换城市或定位变化后不会把旧地点预警、预报、空气质量与新地点实况混在同一页面。
- **声音图标**：整点提醒或全天提醒开启时显示。
- **闹钟图标**：单次闹钟已启用时显示。
- 各工作页共用同一份日期、本地温湿度、分钟时间以及声音、Wi-Fi、闹钟状态；这些状态由统一的逐页状态栏管理，Wi-Fi 图标直接反映射频实际开关状态。内部页面现在各自读取所需网络状态，不再通过公共 UI 头间接取得；切换页面或重建界面不会改变内容、位置、显示条件或图标缓冲复用方式。
- 工作页以及关于本机、网络检测、设置页的切换和界面重建统一使用同一套页面生命周期管理；本次结构维护不改变八个工作页的内容、排序、开关或操作方式，也不改变辅助页的进入、返回和超时规则。
- 位图、数字时钟、全天进度、OTA 面板、可见页同步和基础控件的公共接口已收窄为各自真实依赖，减少后续维护时无关模块相互牵连；这项内部整理不改变任何页面像素、刷新频率、联网规则或操作方式。
- 屏幕尺寸和局部刷新参数现在由独立内部配置统一维护，显示、天气、设置和小智激活相关实现只加载各自需要的接口；页面尺寸、局部/全屏刷新判定、天气同步和用户操作不变。
- 配网、天气、NTP、HTTP 和后台同步继续使用原有功能入口，但内部工具已经改为各模块直接声明依赖；这项维护不改变网络请求顺序、天气数据、失败重试或用户操作。
- 离线、未配网、OTA 阻断和配网重试状态仍按原事件或超时进入等待，不会持续轮询；内部测试现可直接执行这些等待，响应时间和用户操作保持不变。
- 开启离线模式或恢复出厂设置时，仍会在关闭网络或重置配置前取消待处理的手动同步、网络检测和 OTA 请求；本次维护不改变用户看到的结果、确认流程或操作方式。
- **电池图标**：显示估算电量；八个工作页共用同一份电池状态，每次只刷新当前页面。检测到充电时按整秒闪烁，充满或拔掉充电器后会根据 ADC 趋势停止闪烁。由于硬件没有独立 CHG/VBUS 检测引脚，插拔识别可能有短暂延迟。
- 页面显示、充电动画和省电等待会复用同一次电池状态读取，减少空闲运行开销；采样频率、图标和使用方式不变。
- **全天进度条**：八个工作页共用 60 段进度条，每段约代表 24 分钟，只在进入页面或跨过下一段时局部刷新。
- 全天进度条在各页面内部复用同一套绘制与边界规则；变化小段会一次写入共享画布缓冲，并只刷新该小段。本次维护不改变段数、位置、刷新时机或页面显示效果。

设备优先使用局部刷新。秒级页面只更新变化的数字或小区域，低频页面会等待到下一次分钟、日期、传感器或网络数据变化再唤醒刷新。

温湿时钟只在本地传感器数据真正变化时更新温湿度文字、舒适度表情和趋势箭头；秒牌仍保持逐秒刷新，白天每分钟、夜间每两分钟的传感器采样规则不变。

声音、Wi-Fi 或闹钟图标变化时只刷新对应状态，不会重复处理未变化的温湿度；切换页面后仍会立即显示当前传感器数据。

设备内部仍会统计显示刷新情况，但正常分钟窗口如果全部是局部刷新，不再额外输出周期性诊断日志；只有发生全屏刷新时才记录原因。这不会改变任何页面内容或刷新时机。

## 3. 八个工作页面

在工作页面短按 **BOOT**，设备会按照用户保存的页面顺序切换，并自动跳过已经关闭的页面。所有页面均可关闭，但系统会阻止关闭最后一个已启用页面。

八个页面的编号现在由显示、存储和测试共用同一份内部定义；本次维护不改变已保存顺序、页面开关、按键操作或升级数据。

### 3.1 天气时钟

显示大号时间、日期、电池、当前天气、天气预警、本地温湿度、趋势箭头、状态图标和动画区域。

- 时间和必要动画按秒局部刷新。
- 日期、分钟时间、秒、动画和秒进度按各自变化频率局部更新，整点提醒继续按用户设置执行。
- 天气、预警和本地缓存缺失或到期时，进入该页会按需联网同步。
- 离线模式、低电量、配网或 OTA 期间不会发起普通天气同步；低电量/配网画面即使使用天气时钟的底层布局，也只用于显示，不会因此打开网络。

### 3.2 图片时钟

时间保持原有方形点阵。每日文字两侧的双线随文字长度调整，文字较长或为空时不显示装饰线；图片轮换和分钟级时钟更新保持不变。

显示本地图片、大号时间、每日文字和本地温湿度摘要。

- 内置图库按星期选择对应图片，每天切换一次。
- 内置星期一和星期日图片使用各自优化后的黑白阈值与边缘淡化参数，抖动和反色均关闭；其它工作日图片保持原显示效果。
- 上位机写入自定义图库后，切换周期默认是 `24h`，可在 `设置 / 显示 / 图片切换` 选择 `30m / 1h / 6h / 12h / 24h`。周期以设备本地时间每天 `00:00` 为基点：`24h` 每天零点切换，`12h` 在零点和中午 12 点切换，其余周期依次按整点或半点边界切换。内置图库固定按星期每天切换，不能调整周期。
- 自定义图库的临时读取内存只会在实际使用自定义图片时从 PSRAM 申请；只使用内置图库不会为该功能额外预留内存。PSRAM 暂时不足或自定义图片读取失败时仍会显示对应内置图片并稍后重试，不会占用关键内部内存。
- 自定义图片临时读取失败时，设备会保留内置图片并按分钟有限重试；恢复后会自动显示自定义图片，连续失败不会造成反复刷新或持续读取。
- 每日文字只在图片时钟需要时获取；当天已有数据时不会重复联网。
- 页面重建后会重新绘制图片、时间和每日文字，显示内容、切换规则与原操作方式不变。

### 3.3 天气看板

底部天气建议依据今天的日间预报，不代表此刻的实时天气。“今日预报有雨雪，建议带伞”可能在当前晴天时显示，表示当天预报包含雨雪；缺少今天的有效预报时显示等待提示，不沿用昨天的建议。

显示当前城市、实时温度、天气、空气质量、湿度、风力、日出日落、距离下一次日出或日落的时间、天气预警和未来六天天气。

- 天气缓存缺失或到期时，进入页面会排队同步完整天气数据。
- 日出日落倒计时按分钟局部刷新。
- 本地温湿度与顶部状态只在数据变化时刷新。
- 实时天气、预警、预报、空气质量和日出日落在固件内部共用同一套天气数据结构与容量定义，避免维护时解析结果和页面格式化使用不同尺寸；显示内容、同步规则和操作方式不变。

### 3.4 温湿时钟

显示时、分、秒三块高对比数字卡，以及本地温度、湿度、趋势箭头、舒适度表情、日期和农历。

- 秒数每秒局部刷新；普通秒跳直接更新像素缓冲并只发送发生变化的数字区域，局部区域会转换为正确的屏幕位置，不会出现内存时间已经变化但数字牌停住的情况，也不会因逐像素绘制而重复刷新整张数字卡。页面按真实秒边界休眠和唤醒，不再在两秒之间固定轮询多次。
- 温湿度白天每分钟采样，夜间每两分钟采样。
- 趋势箭头根据最近四小时有效样本的滚动平均变化计算，重启后重新积累。
- 页面对象构建和运行刷新已做内部隔离；页面重建会完整恢复数字牌、温湿度、趋势/表情、日期和农历对象，同时继续复用像素缓冲，不改变显示、刷新频率、按键操作或已有数据。

### 3.5 日历

显示当前月份日历、星期栏、农历和节日信息。

- 当前手动日期时间、RTC 有效时间和农历日历共同支持 `2024–2035`；超出范围的时间不会作为有效设备时间使用。
- 支持范围内的农历日期、闰月和二十四节气已按香港天文台公历与农历日期对照表校准。
- 日历主体只在进入页面、日期变化、月份变化或校时跨日后重绘。
- 页面重建后的首帧会强制重绘日历，不会沿用旧页面的日期缓存。
- 设备日历与电脑预览共用同一套星期栏、日期格和今日高亮布局，后续调整时两端会保持一致。
- 极少数需要第六行的月份，在当前日期进入第六行后会隐藏已经过去的第一行并整体上移，保证当前日期可见。
- 当前日期位于最底行时，黑底白字高亮框仍会完整保留底部圆角，不会被屏幕边缘裁切。

### 3.6 温湿历史

显示最近 24 小时的本地温度和湿度曲线。后台传感器采样和小时历史记录不受当前页面影响。

- 设备页面与电脑预览共用同一套曲线、时间刻度、纵轴和极值标记布局，预览时间轴与实机保持一致。
- 页面可像其他页面一样开启、关闭和排序。
- 如果它是唯一启用页面，系统会继续停留在该页，不会形成自动返回冲突。
- 小时样本会在完整保存后一次性更新到曲线；读取历史时不会出现一部分新、一部分旧的数据，NVS 中已有记录和升级兼容方式不变。
- 页面对象重新建立后会立即重绘曲线、刻度和极值，不会等待下一小时样本才恢复显示。

### 3.7 小智 AI

支持本地唤醒、语音对话、屏幕字幕、回复播放、单次闹钟、番茄钟和天气城市设置。

- 只有进入小智 AI 页面后才启动高功耗语音服务。
- 等待云端回复音频期间，空的播放队列会休眠等待新数据，不会以毫秒级频率持续轮询；语音内容、首包缓冲和播放顺序不变。
- 首次使用可能需要按屏幕提示完成小智服务绑定。
- 已绑定设备会直接恢复保存的服务配置；未绑定设备仍按原流程优先显示并播报绑定 ID。只有提示音和数字完整播放后才记为已播报；如果音频资源暂时忙碌或任务未能启动，设备会在后续激活轮次重新尝试，不需要用户切页或重启。
- 未绑定或服务激活失败时仍会按原间隔自动重试；请求和响应临时区会在重试之间复用并清零，减少长时间等待绑定时的内存碎片，不改变绑定步骤和提示。
- 服务端重复确认完全相同的绑定配置时，设备会复用已有内容，不再重复写入 Flash；绑定恢复、重新绑定和恢复出厂保留规则不变。
- 待唤醒时说唤醒词开始对话；页面显示“小智准备中”时请等待服务初始化完成。
- 如果服务端只识别到半句话且没有给出回答，页面会显示“没有听完整”，可以直接补充或重新说一遍；继续安静约 12 秒后会自动回到等待唤醒词状态。
- 用户字幕、小智回复、情绪和播放结束状态使用同一套会话处理规则，连续对话、告别返回和字幕最短显示时间保持一致。
- 小智页面状态更新会先形成完整快照再刷新界面；资源暂时忙碌时会保留上一份完整状态，不会显示一半新、一半旧的字幕或状态。
- 小智对话、重试和页面生命周期现在直接共用同一状态快照入口，内部不再经过重复转发层；状态文字、字幕、表情、唤醒和操作方式没有变化。
- 语音服务握手、普通回复和 MCP 工具消息共用受检会话缓冲；异常超长文本会结束本轮会话，不会覆盖相邻内存。
- 小智监听只会在成功取得麦克风和音频硬件后启动；若闹钟、番茄钟或提示音正在播放，会等待音频释放后按既有流程重试，不会带着不完整音频状态进入监听。
- 查询设备温湿度、电量和音量时，状态文本使用固定容量缓冲生成；设备内存紧张时会放弃本次查询，不会持续占用临时内存或影响后续对话。
- 小智音频在发送、解码、采样率转换和进入播放队列前都会检查数据长度；异常音频只结束当前对话，不会继续读取超出缓冲区的数据。
- WebSocket 接收、Opus 编码和音频解码临时区会作为同一块 PSRAM 在连续对话间复用，并在每轮对话前后清零；不再为每轮对话单独申请编码区。这不会让麦克风、扬声器、Wi-Fi 或语音任务在离开小智页面后继续运行。
- 每轮语音连接会统一管理 WebSocket、TLS 和联网互斥资源；握手、缓冲或音频初始化中途失败时也会自动收尾，不会因为一次失败长期占用联网资源。连接方式、重试时间和语音操作不变。
- 首次绑定码的短文本参数使用静态任务互斥保护的固定槽在播报任务间安全交接，不再为每次播报申请普通堆或在复制期间关闭中断；小智初始化失败时该状态也会完整回滚并允许重新初始化，绑定码仍按原提示音和数字顺序播放，失败时仍会在后续激活重试。
- 页面状态、字幕和表情只在内容实际变化时刷新；离线、未配网或等待重试期间不会反复刷新相同提示。
- 配网切换、页面资源恢复或整屏重建后，小智状态、表情和正在运行的番茄钟会在新页面对象上立即恢复，不会沿用已经失效的旧显示引用。
- 离线模式或尚未保存 Wi-Fi 配置时，小智会安静等待配置变化，不会周期性启动网络；保存配网、切换离线模式或离开页面后会立即响应。
- 绑定或服务连接失败后会按约 15 秒间隔自动重试；等待期间离开页面、闹钟和番茄钟等操作仍会立即响应。
- 离开页面或进入连接失败重试后，普通语音会话会停止，并释放该页面持有的网络和电源资源；闹钟和正在运行的番茄钟继续后台计时。
- 如果小智退出时天气、网络检测、OTA 或其它联网任务仍在使用 Wi-Fi，设备会把关闭请求交给常驻联网任务串行处理，等最后一个使用者完成后再关闭射频，不会从语音任务中途打断新的联网窗口；关闭完成会立即结算该请求，不会把旧请求带到下一次联网后误关连接。被正常业务占用时只等待状态变化，不会周期轮询；如果底层驱动实际关闭失败，重试间隙也会继续抑制无效自动重连，并按约 `1/2/4/8/16/32/60` 秒渐进重试、封顶 60 秒，直到射频关闭或新的联网操作成功接管，避免偶发连续失败后 Wi-Fi 长期保持开启。
- 提示音、闹钟、报时和小智语音结束后仍会关闭音频硬件；重复使用音频时复用固定对象存储，减少长期运行中的内存碎片，不会让 Codec 在空闲时持续耗电。
- 闹钟或番茄钟完成提醒与小智语音重叠时，会通过同一音频等待规则接管硬件；最长等待、按键停止、提示音次数和小智恢复方式不变。
- 小智回复音频的队列和播放任务仍只在对话期间运行；内部控制信息会复用固定存储，连续多轮对话时可减少内部内存碎片，退出页面后的资源释放方式不变。
- 唤醒词和语音识别使用的中间队列以及两个识别任务的小型控制信息会复用固定存储；较大的任务栈仍只在进入小智页面后使用，并在离开时释放。离开小智页面时麦克风、识别任务和音频硬件仍会停止，保留固定控制信息不代表设备继续监听。
- 小智页面功耗明显高于其他页面，长时间运行会使 PCB 发热，并可能让板载温湿度读数偏高。

### 3.8 聚合时钟

晴天使用弧形光晕和放射线，雨天使用波浪云层与斜雨线；这些是随天气结果切换的静态图案，不会持续播放动画。

测试版天气区随整点同步结果切换晴雨图案，样式相同不重复重绘，同步失败保留原内容。不进行日出日落过渡，也不增加动画刷新。只在页面可见时绘制，时间数字仍按秒更新；原有手动同步和缺数据补拉保持不变。

天气区采用反显标题和白底正文；日期区使用细边框，边缘及底带点阵模拟灰度。装饰为静态内容，不额外增加刷新频率。

显示秒级时间、当天天气及最高/最低温、公历日号、农历月份和日期、本地温湿度。默认排在最后，在“设置 / 显示”中可关闭或排序。

- 秒、分、时只更新变化的数字块；日期随日期变化更新，个位日号不补零。
- 天气共用整点缓存及缺失补拉；不因空气质量单独失败而重复请求。
- 本地采样：06:00–21:59每分钟，22:00–05:59每两分钟。隐藏时停止该页绘制，必要后台采样继续。
- 离线模式下不可启用。升级自动追加新页，保留旧页面配置，无需清空NVS。

## 4. 配网页

### 4.1 进入配网

设备没有联网配置且未开启离线模式时，会在开机后自动进入配网。需要重新配置时，也可以通过恢复出厂或离线模式退出流程进入配网页。

1. 连接设备热点 `WeatherClock-xxxx`。
2. 等待手机弹出认证页，或手动访问 `http://192.168.4.1/`。
3. 按需填写以下字段：
   - **主 Wi-Fi 名称（SSID）**：可以从扫描列表选择，也可以手动输入。扫描列表最多显示 32 个热点；刷新页面会重新扫描，内存暂时不足时会显示明确提示，不影响手动输入名称。
   - **主 Wi-Fi 密码**：当前首选网络的密码。SSID 未改变时可留空继续使用原密码。
   - **备用 Wi-Fi 名称和密码（选填）**：主 Wi-Fi 不可用时自动尝试；不需要备用网络时留空。备用 SSID 未改变时，密码也可留空继续使用原密码。
   - **和风天气 API 密钥**：用于天气、预警、预报和空气质量。
   - **和风天气 API Host**：在和风天气控制台“设置 → API Host”中查看，例如 `abc123.re.qweatherapi.com`。只填写域名，不含 `https://`、端口和路径。
   - **天气城市（选填）**：例如“杭州”或“杭州市”；设备会清理空白和末尾“市”，并通过和风天气验证。留空时使用公网 IP 自动定位。
   - **离线日期和时间（选填）**：仅在不使用 Wi-Fi 时填写；正常连接 Wi-Fi 时可以留空。

配网页按“联网配置、天气服务、离线使用”分区显示；附近 Wi-Fi 使用紧凑列表，验证中、成功和各类失败会使用不同状态提示。页面布局变化不改变字段含义、保存顺序或验证规则。

设备支持路由器允许的最长 32 字节 Wi-Fi 名称，并会把该名称完整交给无线驱动。`v1.5.29` 首次启用账号专属 API Host，因此从更早版本升级后必须重新进入配网页补填该字段；其它字段会继续显示或复用已保存配置。

旧版本只保存一个 Wi-Fi 的配置会自动作为主 Wi-Fi 使用，OTA 升级后不需要恢复出厂。每次联网先尝试当前首选网络；单个网络连续失败达到上限或连接等待窗口耗尽后，本轮最多切换一次备用网络。备用连接成功后会成为新的首选网络，下次优先尝试；以后原网络重新可用并在备用失败时连接成功，也会按同样规则再次晋升。

如果主、备 Wi-Fi 都不可用，设备不会在两者之间无限循环。普通工作模式会结束本轮连接并进入原有同步失败退避，避免 Wi-Fi 长时间高功耗运行；配网模式会继续保留设备热点和结果页，等待用户修改名称或密码。串口只记录槽位、SSID 和密码长度，不输出密码全文。

点击保存后，页面会立即显示“正在验证网络配置”，设备不会为了验证而重启。后台网络任务会在 AP+STA 模式下连接用户路由器，并通过账号专属 API Host 验证 API 密钥；填写手动城市时还会继续验证城市。页面会自动查询验证结果。全部通过后，设备自动结束配网并关闭热点。Wi-Fi 密码、API 密钥、API Host 或城市有误时，热点不会关闭，结果页会显示对应原因；如果手机因路由器信道切换丢失了当前网页连接，重新打开 `http://192.168.4.1/` 仍会在表单上方看到最近一次验证状态。保存按钮单独位于日期时间输入框下方，不会与输入框挤在同一行。

验证结束后，设备会串行完成从 AP+STA 到配网热点的结果交接，再向手机发布成功或失败状态，避免该阶段与其它 Wi-Fi 启停动作冲突。这项稳定性保护不改变填写字段、结果提示、失败重填或成功后自动关闭热点的操作方式。

如果用户在上一轮验证或结果页仍未结束时重新提交配置，设备会分别识别两次保存。旧页面的迟到请求和旧网络验证都不会覆盖、取消或继续阻塞新一轮；新一轮验证成功后仍会等待对应成功结果送达手机，再按正常流程退出配网。若新一轮输入无效或改为离线配置，也不会误恢复上一轮联网验证。

正常字段可以直接提交。如果自定义 OTA 地址等字段异常过长，配网页会提示“提交内容过长，请缩短自定义字段后重试”，并保留热点等待修改；这次请求不会保存半截 Wi-Fi、API 密钥、城市或地址。

进入配网页时，设备会先显示配网覆盖层，再播放一次配网提示音。普通提示音只启用扬声器，不会同时初始化未使用的麦克风；如果显示首帧造成瞬时内存紧张，设备会短暂等待并有界重试提示音。配网画面继续显示 RTC 恢复出的时分与日期，但不会运行秒动画、GIF、天气和底部工作页刷新。

极少数底层网络异常会使手机不自动弹出认证页，此时仍可手动访问上述地址。设备会停止异常的 DNS 服务，不会让它在退出配网后继续占用资源。

如果手机离开设备热点后再次连接，设备会在最后一个客户端断开时重置 DHCP 租约，使手机可以重新获得 `192.168.4.x` 地址。验证 Wi-Fi/API Key 或正在返回成功结果时会保留当前租约，不会把临时信道切换误判为真正离开。重新连接后若认证页未自动弹出，直接访问 `http://192.168.4.1/` 即可继续配置。

设备屏幕上的配网状态行会随配网模式统一显示；界面因模式切换或资源恢复而重建时，状态行会重新创建并继续刷新，不会沿用已经失效的旧界面引用。

配网页内部的字段解码、配置事件收尾、配置存储、配网启动请求、热点启动与结果交接、恢复出厂清理已经使用更轻量的独立模块；门户活跃状态、断线原因、热点名称、本地 IP 和验证反馈也只能由配网流程写入，其它页面只读取完整快照。热点启动失败仍会保留请求并有界重试，验证失败仍保留配网页，成功时仍等待手机读取结果后关闭热点。这项维护不改变字段名称、中文输入、截断提示、保存结果、超时、热点启动时机、原有配置恢复或按键操作。

配网热点开启并等待用户输入时，后台网络任务会一直休眠到用户保存配置或门户关闭，不再每 30 秒周期空醒；配网页字段、响应速度、验证和成功/失败反馈均不改变。

### 4.2 联网模式

填写 Wi-Fi 后提交，设备会保存联网配置并尝试连接。和风天气 API 密钥和账号专属 API Host 都是天气功能的必要配置；每日文字和 NTP 不使用这两项配置。

设备会把 Wi-Fi 名称、密码、天气 API 密钥和 API Host 作为一组完整配置切换给后台任务；保存过程中不会混用新旧配置，串口日志也不会输出密码、完整 API 密钥或完整 Host。Host 会自动去掉首尾空白并转成小写；旧公共域名、带协议/端口/路径或不属于 `qweatherapi.com` 的值不会生效。

配网完成后，设备会错开执行 NTP、天气和每日文字同步，避免多个 HTTPS 请求同时占用内存。当前启用但暂未进入的联网页面，也会在启动阶段获得一次基础数据预拉。如果启动页只拿到实时天气而预警、预报或空气质量尚未完成，设备会先显示已经取得的实况，并在后台保留一次稍后的完整补拉，不必先进入天气看板才开始获取扩展数据。
如果天气页或图片时钟在自动补拉执行前被关闭，设备会取消对应的启动待办，不会在延迟到期或资源重试后仍为已关闭页面打开 Wi-Fi；手动同步和系统 NTP 校时仍按原入口执行。
如果关闭天气看板但保留天气时钟，自动天气同步只获取实况和预警，不再下载没有页面使用的六日预报与空气质量。重新开启并进入天气看板时，设备会保留可用旧数据显示并立即补齐扩展数据；设置页手动同步和网络检测仍会获取全部天气内容。

普通 HTTPS 同步和小智 WebSocket 建连会共用同一串行网络边界；两者交错发生时，后发任务会等待当前事务结束，避免同时争用 TLS 内存。该保护不会改变用户的同步、OTA 或小智操作方式。

小智保持联网时，天气、时间或每日文字等普通后台同步会复用已经连接的 Wi-Fi，不会为了重复应用同一配置主动断开重连，也不会覆盖小智实时会话所需的 Wi-Fi 省电策略。进入配网或连接确实已经断开时仍会按正常流程重新连接。

设备会在开机时同步一次时间，之后每天本地时间 0 点同步一次。零点同步失败后仍会保留本次每日同步待办，并按正常退避时间重试，不会因为时间已经跨过 00:00 而漏掉当天同步。

设置页手动同步时间属于用户主动发起的单次请求，不受开机或每日同步此前失败后的退避时间限制；按下后会立即尝试联网校时。失败时会正常显示结果，但不会额外安排一次没有请求来源的后台唤醒。开机同步和每日零点同步仍保留自动重试：RTC 时间不可信时约 15 秒后重试，时间已经可信时约 5 分钟后重试。

### 4.3 手动天气城市

手动城市优先于 IP 自动定位，可以通过以下方式设置：

- 配网页的“天气城市”字段。
- 上位机写入自定义资源配置。
- 小智语音，例如“把天气城市设置为杭州市”。

设置页 **网络 > 天气城市** 会显示“自动”或当前城市。自动模式下按 BOOT 会提示通过配网页、小智或上位机网页设置；手动模式下按 BOOT 并二次确认可清除城市，恢复 IP 自动定位。清除后会立即排队同步一次天气。

如果和风天气无法识别输入城市，该城市不会生效；超时情况下设备会保留规范化城市，并在下一次天气同步时重新验证。

城市保存后无需重启，会立即作为一份完整文本供配网页、小智、设置页和天气同步使用；即使同步过程中修改中文城市，也不会显示半截文字或把新旧城市混在一起。配网页在线验证无法识别该城市时会保留热点和当前输入，等待用户修改或清空为自动定位。

配网页、上位机资源、小智、已保存配置和设置页显示使用同一套城市长度与校验限制，不会出现某个入口接受后、另一个入口又按不同长度截断的情况。

通过小智连续设置城市时，设备会按每次确认的先后顺序保留最新请求；即使前后两次城市名称相同，也不会被前一次保存流程误清。语音回复完成后仍按原流程更新当前天气、预警、预报和空气质量。

### 4.4 离线模式

如果不填写 Wi-Fi，但填写有效日期时间，设备会写入 RTC、开启离线模式并进入工作状态。

离线模式开启后：

- Wi-Fi 和所有普通网络服务停止。
- NTP、天气、预警、每日文字、网络检测和 OTA 均不可用。
- 天气时钟、图片时钟、天气看板和小智 AI 自动关闭，并且在离线期间不能重新开启。
- 日历、温湿时钟和温湿历史等本地页面继续工作。
- 已缓存的数据不会被主动删除。
- 离线状态会保存并在重启后继续生效；设置页、页面开关、天气、OTA 和小智会立即使用同一状态，不需要再次开启。
- 开启离线模式的短暂切换期间即使恰逢路由器断线，设备也不会重新连接一次；正常联网模式下的意外断线仍会自动恢复。

关闭离线模式时：

- 已保存 Wi-Fi、和风天气 API 密钥和账号专属 API Host：可以直接关闭。
- 缺少 Wi-Fi、API 密钥或 API Host：设备要求二次确认，然后进入配网页；完成联网配置后才退出离线模式。

## 5. 设置页面

短按 **KEY** 进入设置。左侧是一级菜单，右侧是对应的二级项目；选中项使用黑白反转显示。

设置导航和需要二次确认的操作会在按键、界面与 OTA 任务之间安全交接。一级/二级焦点、页面开关/排序模式和当前选择项会作为一份完整状态更新，快速按键不会短暂组合出错误焦点或跳到其它项目；从关于本机或网络检测返回，以及 OTA 保持检查更新页面时，也不会沿用上一条路径的状态。按键方式和 30 秒无操作超时保持不变。

设置导航的完整写入口现在只保留给内部导航和设置动作，页面绘制、主循环及其它普通模块只能读取当前快照，降低后续维护误改焦点或模式的风险。菜单内容、按键、页面排序、二次确认和超时行为均未改变。

从二级菜单返回一级菜单时，原有的短暂防误退出保护仍然有效；退出设置页或重新进入后，这个临时状态会被清除，不会让上一轮设置操作拦截新一轮长按。800ms 保护时长、菜单层级和按键方式均未改变。

恢复出厂、关闭离线模式和清除手动天气城市的二次确认现在也只由设置动作和导航内部维护，页面绘制只能读取是否正在确认，降低其它模块误清除或误触发确认的风险。确认次数、提示文字、持续时间、按键和退出方式均未改变。

设置、关于本机和网络检测在屏幕上始终互斥显示；快速进入或返回时不会残留另一张辅助页面。入口、内容、检测进度、按键返回和 30 秒无操作超时均保持原有方式。

保存、同步、超时和确认提示会作为完整文本与显示时限一起更新；当前同步类型和 60 秒超时截止时间也会作为完整状态交接。快速按键、迟到的后台结果或同步完成时不会出现半截提示、混用新旧时限或错误结束另一项同步；同一同步项目超时后可以立即重试，上一轮迟到的结果不会取消新请求或覆盖新反馈。提示文案、持续时间和操作方式不变。

保存或恢复联网配置时，Wi-Fi 信息、天气 API Key 和 API Host 会作为一组完整配置生效；后台网络任务不会读取到只更新了一半的配置，密码、完整 API Key 和完整 API Host 也不会写入串口日志。

### 5.1 网络

- **同步时间**：立即执行一次 NTP 同步。
- **同步天气**：同步实时天气、天气预警、未来预报和空气质量，并同时更新天气时钟与天气看板共用缓存。
- **更新一言**：立即刷新图片时钟底部的每日文字。
- **天气城市**：查看自动/手动定位状态；手动模式下可二次确认恢复自动定位。

网络检测运行时会随着每个项目完成即时更新。DNS 只有服务真正解析出地址时才显示成功，异常空结果会显示失败。检测结束后页面仍按原规则在无操作约 30 秒后返回，但空闲期间只等待按键或返回截止时间，不再持续轮询屏幕。

同一轮网络操作会按开始时的请求统一返回结果；操作期间新增的同步请求会留到下一轮处理，不会被前一轮结果误清除。

### 5.2 声音

- **音量**：20%、40%、60%、80%、100% 五档循环调整并试听。
- **声音选择**：循环切换内置提示音并试听。
- **整点提醒 7:00–22:00**：仅在白天指定时段整点播放。
- **全天提醒 0:00–24:00**：开启后优先级高于整点提醒，全天整点播放。

两种提醒都关闭时不播放。小智 AI 会话、OTA 或其它关键音频占用期间，系统会避免并发抢占 Codec。
如果系统暂时无法取得播放所需的唤醒和频率资源，本次提示音会安全跳过并释放播放状态；后续提醒或试听仍可再次尝试。
音频忙碌时快速连续调整声音设置，系统只保留一次待处理试听，并在可播放时使用最新选择，避免随后重复播放多次。
如果待处理试听等待期间进入低电量模式或开始 OTA 下载，设备会取消本次异步播放，不会在受保护阶段稍后突然打开 Codec；退出受保护状态后的下一次正常试听和整点提醒不受影响。
设备没有在后台运行厂家音频演示任务；只有整点提醒、试听、闹钟、番茄钟提示或小智会话真正需要时才打开对应音频资源，结束后按统一流程释放。
按键处理和 OTA 更新入口已与无关的页面、网络和全局状态实现解耦；按键操作、检查更新、下载、校验和重启流程保持不变。
Codec 与传感器的 I2C 寄存器写入不再反复申请内部堆，连续试听或进入小智页面时更不容易因堆碎片造成瞬时资源压力；声音、传感器和页面操作方式不变。
小智退出时的音频资源诊断使用独立同步状态，不再跨任务读取正在创建或释放的 Codec 指针；这只提升异常诊断稳定性，不改变声音设置和使用方式。
整点提醒、试听、闹钟、番茄钟和小智共用同一个原子播放权；多个声音同时到达时仍只允许一个使用 Codec，频繁检查忙碌状态也不会额外关闭跨核中断。
音频层会分别确认扬声器和麦克风是否真正就绪；Codec 只完成部分初始化时，不会发布不可用资源或把空麦克风句柄交给驱动。本次播放或小智进入会安全结束，后续操作仍可重新尝试。
如果 Codec 连有效播放句柄都没有建立，设备会在本次播放返回前停放音频引脚并归还高性能资源，不会因一次初始化失败持续保持较高功耗。
生产音频会直接复用板级 Codec 已经拥有的 ES8311/ES7210 I2C 控制接口，不再为每次会话注册重复且无人使用的设备句柄；声音行为和硬件地址不变。
普通整点提醒、设置试听和配网提示音的单声道转换缓冲已改用 PSRAM，为 Wi-Fi、HTTPS、显示和音频并发保留更多内部内存；提示音内容、音量、淡入淡出、停止方式和小智语音均不变。
天气、每日文字、小智和 OTA 共用的联网事务锁改为独立静态常驻资源，并由专项测试直接验证初始化失败重试和互斥争用，减少冷启动内部内存分配失败和长期碎片风险；联网顺序、等待时间及用户操作不变。
OTA 状态快照与配网页 AP 名称/IP 文本快照现在也和其它永久运行态复用同一套应用期常驻锁所有者，清理了重复初始化模板；OTA 来源、进度界面、重启、配网反馈、Wi-Fi 操作和显示地址均保持不变。
OTA 清单的版本、下载地址和 SHA256 固定容量现在由 OTA 模块单独维护，纯解析接口不再携带无关的显示与应用状态依赖；清单格式、来源顺序、下载校验和用户操作完全不变。
每日文字内容和成功更新时间会作为同一份快照更新，避免后台联网与页面刷新交错时出现新文字配旧时间；内部缓存仍为 160 字节，22 字限制、获取频率和显示方式不变。
网络与音频电源锁的深度计数现在复用统一的静态常驻任务 mutex；如果该资源初始化失败，会在创建半初始化电源锁前停止并支持后续重试，正常 light sleep、联网和声音行为不变。

设备启动动画和首次联网任务退出后，FreeRTOS 可能还需要很短时间回收临时任务内存。若此时网络同步、OTA、传感器、界面、按键、闹钟或番茄钟常驻任务因瞬时内存压力创建失败，固件会在有限时间内只补建失败服务，不会重复启动已成功服务，也不会无限重试。正常开机速度和功能不变；补建仍失败时可通过串口中的任务名和失败位图定位。
网络、音频和音频性能锁的类型、名称、句柄与嵌套计数现在按每把锁成组维护，减少后续维护时把锁句柄和引用计数配错的风险；正常 CPU 频率、light sleep、联网、播放和小智使用方式不变。
本地温湿度的当前值、趋势和刷新版本也会作为一份任务级快照发布，页面和小智不会在后台采样交错时读到不同批次的数据；采样间隔、箭头和显示方式不变。
电池运行态、本地温湿度当前快照和 48 槽小时历史现在共用同一套应用期常驻锁所有权模式，清理了重复初始化模板；采样、充电判断、NVS 历史、页面读数和操作方式均保持不变。
传感器、电池、小时历史、系统时间和电源锁的内部接口现在分别声明自身真实依赖，减少后续维护时无关模块相互牵连；采样频率、RTC、充电判断、light sleep 和页面读数均保持不变。
电源管理实现也只加载自身需要的应用元数据、ESP PM、日志和锁契约，不再引入完整应用状态；该调整只收窄维护边界，CPU 频率、light sleep、联网和音频行为保持不变。
小智内部只为日志标签和版本信息读取轻量应用元数据，不再同时载入无关的显示、天气和系统状态声明；绑定、唤醒、对话、MCP、音频、联网和页面操作均保持不变。
共享音频和提醒编排也只读取自身需要的日志、任务、电池与硬件声明，不再同时引入无关的显示、天气、网络和 OTA 内部状态；整点提醒、设置试听、配网提示、小智音频、功耗和操作方式均保持不变。
天气定位文本和 QWeather 响应处理也只加载自身需要的天气类型、JSON、缓冲和日志能力，不再带入无关的显示、OTA、音频和系统状态；定位城市、天气数据、失败提示和页面显示保持不变。
通用 HTTP、IP 定位、配网天气校验、QWeather 客户端和天气运行态现在也遵循同一轻量依赖边界；联网请求、解析、缓存、事件通知和用户操作保持不变。
配网 AP 密码、门户地址以及固件内置的 OTA 主备清单地址现在由同一个轻量编译期配置契约维护；配网、网络检测和更新行为不变，私有部署地址仍不会进入受版本控制的源码。
NTP 同步和最近成功同步时间查询现在使用独立轻量服务接口；启动时间恢复、定时校时、RTC 更新、网络检测和页面信息保持不变。
RTC 时间恢复与系统时间回写也使用独立的内部接口；设备仍会在启动时尝试恢复有效 RTC 时间，联网校时或离线手动设置后仍按原流程回写 RTC，闹钟重新安排和页面刷新不变。

通用 HTTP 文本请求和启动联网预算现在也分别使用独立轻量接口。普通请求仍固定使用 10 秒超时，开机联网预算不足时只按剩余时间缩短；天气、IP 定位、每日文字、网络检测和 OTA 检查仍沿用原有 URL、证书、启动错峰、失败重试和显示行为，这项内部维护不改变任何用户操作。
启动画面的完成状态现在也只允许应用主流程更新，联网和天气模块只能读取该状态并继续执行原有首分钟错峰与内存保护，减少后续维护意外提前集中 HTTPS 请求的风险。开机画面、进入工作页的时机、天气补拉、Wi-Fi 次数和用户操作均未改变。
启动时间判断与后台联网休眠时长也直接复用各自已有的统一规则，不再经过网络聚合模块重复转发；开机校时、整点同步、低功耗等待和按键唤醒行为保持不变。
OTA、启动联网和小智现在共用同一份轻量 Wi-Fi 生命周期接口；连接等待、配网热点、射频按需关闭和小智会话保活方式不变。
天气城市、实时天气、预警、预报和空气质量查询也统一使用专属客户端接口；配网验证、天气页面缓存和小智设置城市的使用方式不变。
IP 自动定位也使用独立轻量接口供天气更新和网络检测共同调用；定位地址、城市结果、失败提示和用户操作保持不变。
天气整批更新的成功、失败和资源延期结果也使用独立内部接口；后台同步与网络检测的请求顺序、缓存和页面行为保持不变。
配网启动与验证结果交接、每日文字抓取也分别使用专属内部接口；配网成功/失败反馈、每日文字重试、缓存和图片时钟显示保持不变。
网络检测会话控制与九项检查也使用专属内部接口；离线或未配置反馈、检测顺序、超时、页面结果和用户操作保持不变。
配网 HTTP 与强制门户 DNS 生命周期也使用各自专属内部接口，路由处理器保持配网实现私有；强制门户 DNS 的启动、停止和重复进入使用单一任务状态交接，快速重复进入或退出配网不会建立重叠 DNS 服务，浏览器兼容、表单提交、验证反馈和热点行为保持不变。
四小时趋势样本与 48 槽小时历史现在共用一份稳定数据定义，主机验证也直接使用固件中的真实结构，不再复制另一套测试结构；NVS 数据、重启恢复、历史曲线和页面操作不变。
配网、同步、OTA 和启动流程共用的应用事件编号与事件组资源由同一个内部模块统一管理，并继续使用静态常驻资源；初始化尚未完成或启动失败清理后，后台调用会安全跳过，不会误用无效句柄。事件触发、等待超时和用户操作不变。
小智页面的状态快照锁同样使用静态控制块，减少启动时内部内存分配和长期碎片风险；唤醒、字幕、表情、番茄钟和页面操作不变。
小智页面活动、唤醒和暂停所用的内部事件组也使用静态控制块，进一步减少启动动态分配；页面进退、闹钟和番茄钟行为不变。
按键 GPIO 若在极少见的硬件初始化异常中失败，固件会有序停止按键任务并保留其它后台服务，不再让任务入口直接返回引发不确定行为；正常按键、防抖和页面切换不变。
RTC 和 SHTC3 建立设备前也会确认共享 I2C 总线可用；显示和共享 I2C 总线由固件各自唯一持有，RTC、温湿度传感器与音频始终复用同一条 I2C 总线，不会因不同功能重复创建设备总线。SHTC3 对象由传感器模块使用应用期静态存储持有，减少启动普通堆分配失败和长期碎片，完整销毁时仍会归还自身句柄。每次采样只在传感器确认唤醒后进行，结束后会确认进入休眠，瞬时休眠失败仅做一次短重试，避免异常 I2C 状态增加空闲功耗。GPIO、传感器地址、首次采样顺序、采样间隔和页面读数不变。

### 5.3 显示

- **页面开关**：开启或关闭页面；离线模式下不能开启联网页面；不能关闭最后一个已启用页面。页面开关变化会立即安全地提供给切页和后台联网判断，显示与同步规则不变。
- **页面顺序**：只显示已启用页面。KEY 选择，BOOT 将当前页面与下一项交换；保存后开机默认进入第一项。内部通过启动期固定任务互斥一次保存和读取完整顺序，并让同一次排序使用同一份页面开关状态；快速排序、页面开关变化或同时切页时不会混用前后两批配置，也不会使用只交换了一半的临时排列。若保存失败，设备会保留原顺序和原选择位置，不会出现本次生效、重启后恢复旧顺序的情况。
- **小智节能**：首次刷写或恢复出厂时默认开启；开启后，小智页面连续 5 分钟无有效操作会返回页面顺序第一项。番茄钟运行期间暂停自动返回，之后手动关闭的选择会正常保存。
- **闹钟**：显示单次闹钟时间；有闹钟时可以在这里手动关闭，没有闹钟时显示未设置。
- **图片切换**：仅在存在上位机自定义图库时可调，BOOT 依次选择 `30m / 1h / 6h / 12h / 24h`。使用固件内置图库时固定显示 `24h`，按键不会修改。

以上五项使用两列紧凑布局，尺寸与系统页的网络检测、恢复出厂设置和关于本机一致；设备界面与电脑端预览共用同一套布局，因此两边显示位置保持一致。
闹钟按钮会为右侧状态圆点保留独立区域，开启时完整时间不会与圆点重叠；小智节能文字与页面开关保持相同的居中基线。

小智 AI 不能排在页面顺序第一位，因为高功耗服务不适合作为默认主页。页面顺序必须至少保留一个非小智页面。

### 5.4 系统

- **离线模式**：开启或关闭离线运行。
- **网络检测**：检查本地 IP、公网 IP、IP 定位、DNS、和风天气、NTP、每日文字、公网和 OTA 清单。DNS 项会检查当前保存的和风天气 API Host 与 GitHub 域名，不再检测旧公共域名。本地 IP 和九项检测结果按完整快照更新，连接、续租、断线或后台结果变化时会自动更新且无需重启，不会显示半截地址或半行状态。公网 IP 响应只有在包含合法四段 IPv4 地址时才会通过；服务错误文字、域名或超出范围的地址会显示失败，不再误报成功。
- **恢复出厂设置**：需要二次确认。
- **关于本机**：显示版本、电池、电压、上次满电时间、设备信息和源码仓库地址。设备只有在已经确认进入充电态、会话从 `96%` 以下开始、持续至少 60 秒并跨过满电门槛时才记录；普通拔线、电压回落、高电量开机负载恢复不会创建新记录。高电量充电的平台条件仍会停止图标闪烁，但不写入满电历史。时间低频保存到 NVS，重启后继续显示；由于开发板没有连接充电芯片状态引脚，这仍是 ADC 趋势给出的保守软件判定，并非充电芯片硬件信号。
- **检查更新**：检查并安装 OTA 固件。

关于本机和网络检测的动态内容由各自页面统一维护；界面重建后会重新显示当前设备信息和最新检测快照，不改变进入、长按返回或检测完成后的超时规则。两个页面现在只引用各自实际需要的显示接口，减少后续维护对其它页面的影响；设备信息、检测项目、显示布局、刷新时间和操作方式均保持不变。

网络检测的空闲、运行中和完成状态也使用同一内部类型与结果快照发布；公共页面侧只保留结果重置和只读能力，开始、结束、终止反馈与九项执行只允许联网内部流程调用，逐行结果也只由检测执行器写入，减少维护时产生半套结果的风险。没有打开网络检测页面时，普通工作页不读取这份无关状态。这项内部整理不改变九项检测内容、显示顺序或操作方式。

设置菜单、底部反馈、手动同步状态、页面顺序和检查更新进度也分别由对应界面统一维护；底部反馈与手动同步状态由同一设置反馈模块管理，并继续使用两把独立的应用期常驻锁，减少只供单一所有者使用的生产文件。启动屏、配网状态和设置页内部只引用各自实际使用的显示接口，减少无关页面修改带来的维护影响。启动配置读取与日常配置保存使用独立内部入口，声音、页面开关/顺序和小智自动返回也共用专属持久化入口；NVS 内容、重启恢复、保存时机和操作反馈不变。从配网、关于本机或网络检测返回后会按当前状态重新显示，不改变启动画面、配网状态、按钮顺序、页面排序、30 秒超时、OTA 百分比、速度或进度条。

设置菜单编号、项目数量和手动同步类型在固件内部共用同一份定义，避免后续维护时出现显示、按键与联网操作编号不一致；本次整理不改变用户看到的菜单顺序、文案和操作方式。

## 6. 闹钟和番茄钟

### 6.1 单次闹钟

闹钟只能通过小智语音设置、修改或关闭，目前只保存一个。

- 示例：“明天早上 6 点 30 分叫我。”
- 已有不同时间闹钟时，设置新闹钟会先要求确认覆盖；只有明确确认后才会替换。
- 闹钟与番茄钟完成时间不能落在同一分钟，后设置的任务会被拒绝。
- 闹钟启用后仍在后台可靠计时，任务会直接休眠到下一次目标时间，不再每分钟空醒；修改闹钟、NTP 或手动校时会立即唤醒并重新计算目标。
- 闹钟使用固定提示音，播放后间隔约 5 秒重复，最长持续 1 分钟。
- 任意按键可停止响铃。
- 闹钟响铃后自动关闭，是单次有效任务。
- 重复保存完全相同的闹钟状态不会产生额外 Flash 提交，不影响原有设置、关闭和重启恢复结果。
- 闹钟启用、响铃、时间和覆盖确认会作为同一份线程安全状态更新；状态栏等只需判断启用状态的界面使用轻量读取，快速语音覆盖、后台触发和页面刷新不会读到不同批次的数据。

### 6.2 番茄钟

- 示例：“开始一个 25 分钟番茄钟”“专注 45 分钟”。
- 默认 25 分钟，范围 1 秒至 99 分 59 秒；再次启动会修改当前时长。
- “番茄钟还剩多久”可查询；“取消番茄钟”或“结束专注”可取消。
- 普通“10 分钟后提醒我”属于闹钟，不属于番茄钟。
- 停留在小智页面时，番茄钟完成提示只会暂时暂停语音监听；暂停期间不会重复启动服务，提示音结束后直接恢复待唤醒，不会重新进入小智启动流程。
- 页面切换后继续后台计时，但设备重启后取消。
- 停留在小智页面时，普通时间和番茄钟数字都使用同一套秒级局部刷新；运行中的倒计时会持续更新，不会因为语音服务工作而定格。
- 番茄钟状态、截止时间和完成时间会作为同一份线程安全快照更新；页面切换、后台任务交错或 NTP 校时不会让显示读取到不同批次的数据，倒计时和完成/取消后的普通时钟恢复规则不变。
- 最后一分钟不显示百分秒：分钟显示 `00`，右侧显示剩余整秒。
- 完成后显示完成状态并播放两次提示音；任意按键可停止。
- 单独对小智说“关闭”或“停止”表示退出当前语音页面，不会取消后台番茄钟。

## 7. OTA 更新与刷机

GitHub 公开源码仓库的同版本 Release 会由 GitHub Actions 自动附加两个构建产物：`weather_clock_vX.X.X.bin` 用于 OTA 或单独写入 App 分区，`weather_clock_vX.X.X_merged.bin` 用于从 `0x0` 完整刷写。自动构建只增加固件附件，不会改写该 Release 原有的完整中文版本说明；源码标签同时保存一份有版本标题和连续编号的简化 OTA 说明，供 GitHub OTA 与 Gitee OTA 仓库共同同步。

GitHub OTA 主仓库和 Gitee OTA 备用仓库都由同一次源码构建结果自动更新。源码构建完成后只发送同步事件，两个目标仓库分别从源码 Release 拉取 app/merged，核对大小与 SHA256，并在上传后回读验证；全部通过后才更新自己的 Release 和清单。任一目标暂时失败时仍保留上一版清单，设备不会看到半套固件。

两条自动化链路现在共用同一份双固件命名与校验契约，避免 app 和完整刷写固件只更新其中一侧；现有文件名、校验方式、设备 OTA 操作和串口刷写方式均不改变。

维护工具也使用一份公共参数契约读取 app/merged 名称、大小和 SHA256，避免不同镜像目标漏检其中一个固件；这不会改变用户看到的文件名、更新清单或 OTA 操作。

维护发布流程还会确认在线附件来自当前版本标签对应的最新构建，并核对 GitHub OTA 与 Gitee OTA 两份清单中的 app/merged 大小和 SHA256。同一版本覆盖更新时，仍可访问的旧附件不会被当作新构建完成；用户不需要改变检查更新或下载操作。

如果 GitHub 或 Gitee 临时返回缺失、空值或类型异常的附件/版本列表，维护发布流程会把它视为“尚未同步”并继续有界重试，不会误发布半套固件；这项容错不改变设备检查更新、下载或备用源切换方式。

维护流程会用同一规则核对源码 Release、GitHub OTA 主仓库和 Gitee OTA 备用仓库的 SHA256 与文件大小；摘要字母大小写不影响合法校验，畸形摘要或异常大小会保持上一版在线清单，不会被当作可安装固件。设备端 JSON 格式和更新操作不变。

源码构建和备用镜像工具也共用同一套清单字段、1800 字节 `latest.json` 上限和最近 10 版保留规则。Gitee 自动化部署时会把这份公共契约和镜像同步器一并安装，保证两个 OTA 仓库持续使用一致的 app 与完整固件元数据；这项维护调整不会改变设备或上位机读取的 JSON 格式。

设备内部会安全地把配网、离线模式、报时、音量和小智自动返回等设置同步给后台任务；离线模式现在只能由配置保存和启动恢复路径修改，普通显示、天气、OTA、Wi-Fi 与小智模块不能意外重新开启联网工作。小智自动返回开关仍由独立运行状态统一管理。这些维护边界不改变设置入口、保存方式或重启后的恢复行为。

联网配置、配网页提交、后台同步任务和 Wi-Fi 射频生命周期现由各自的内部模块维护，不再经过统一聚合接口。这只是代码维护边界调整，不改变 Wi-Fi、天气 API Key、手动城市、离线模式、配网反馈或同步行为，升级后不需要因此重新配网或恢复出厂设置。

如果设备内部保存的 Wi-Fi 配置无法交给无线驱动，普通同步会立即结束本轮联网，避免长时间空等；在配网模式中，设备仍会保留配网热点和网页，方便重新填写正确配置。正常 Wi-Fi 连接和配网操作方式不变。

如果配网网页服务在启动阶段异常失败，设备会使用与普通联网相同的完整无线收尾流程；无线驱动未能关闭时仍会保留真实开启状态，便于后续恢复和状态图标提示，避免后台隐藏耗电。正常用户不会看到额外操作步骤。

OTA 的检查状态、下载进度、速度和重启提示也会作为一份完整状态在后台任务与页面之间同步，避免页面偶尔读取到不同批次的信息；检查、确认、下载和重启操作方式不变。

OTA 的 Wi-Fi 收尾现在使用明确的内部所有权模式：普通检查和下载失败会释放网络唤醒锁，只有已校验成功且即将重启的更新才会短暂保持唤醒。检查操作、进度显示、射频关闭和重启时序均不改变。

检查更新或安装更新在等待路由连接时如果超时，设备会立即走 OTA 专用的射频关闭路径，并继续保留底层驱动失败时的自动补处理。这样弱网检查失败后不会让 Wi-Fi 长期保持开启；错误提示、重试方式、更新来源和用户操作均不改变。

如果排队中的 OTA 请求刚好与开启离线模式交错，OTA 任务会在申请网络唤醒锁前再次确认当前模式；设备保持离线并显示离线原因，不会短暂占用网络唤醒资源，也不会把策略阻断误报成 Wi-Fi 故障。

OTA 状态、下载进度和重启静默窗口现在只由更新服务内部维护，其它页面、音频、传感器和普通联网任务只能读取。这样可减少维护中误改更新高功耗门控或重启状态的风险；检查更新、确认下载、百分比、速度、校验和重启操作保持不变。

天气、每日文字或网络检测等普通联网结束时，如果 Wi-Fi 仍由 OTA、配网或小智使用，设备会登记延后关闭请求，并在最后一个使用者退出后关闭射频；未取得本次联网所有权的路径不会误发新的关网请求。同步内容、执行时间、失败重试和用户操作均不改变。

在线清单可以包含供发布页和上位机展示的更新说明；设备检查更新时只保留版本、下载地址、文件大小和 SHA256 校验信息，不会长期占用内存保存这段说明。
OTA 清单中的更新说明使用源码标签内同一份精简摘要，并有固定长度上限；GitHub OTA 与 Gitee OTA Release 都使用这份说明，完整中文编号说明继续保留在同版本 Gitea/GitHub 源码 Release 中，避免说明过长影响设备检查更新。

进入 **设置 > 系统 > 检查更新**：

1. 页面显示当前固件版本，按 BOOT 开始检查。
2. 检测到新版本后，在 60 秒内再次按 BOOT 开始下载。
3. 下载时显示百分比、速度和进度条。
4. 校验成功后显示“即将重启”，再自动重启进入新版本。

固件会自动处理 OTA 下载重定向，并在下载失败或提前退出时关闭本次 HTTP 连接。初始下载地址和跳转地址必须完整放入受保护的 URL 工作区；空、缺失或过长的跳转会直接判定失败，不再静默截断。失败不会切换启动分区，可以重新检查后再次下载。
OTA 诊断仍会保留状态码、地址长度、固件大小、电量、信号强度、阶段和错误码，但不再打印完整的清单地址或跳转地址，因此自定义服务器地址和临时签名查询参数不会进入串口日志。

固件成功下载并确认 HTTP 数据完整后，现在会在最终镜像校验和启动分区切换前释放已经使用完毕的 4 KiB 传输缓冲。更新来源、进度、完整性校验、失败回退、重启流程和操作方式均保持不变。

下载开始时的 Wi-Fi/电池诊断、SHA 文本格式化和新镜像描述暂存也只在各自实际使用阶段保留，进一步降低 OTA 任务栈压力，不改变下载和校验顺序。

OTA 使用远程主源和事件驱动的 GitHub 备用源。源码构建和镜像校验尚未完成时，备用源可能短暂保留上一版。

以下情况不能执行 OTA：离线模式、低电量模式、配网过程中或已有 OTA 正在运行。

OTA 检查或下载期间，普通后台联网同步会等待 OTA 状态变化；下载百分比、速度和进度条仍正常更新，但不会反复唤醒无关的天气、时间或每日文字任务。

### 7.1 App bin 与 merged bin 的区别

- **App bin**：写入当前 OTA App 分区，适合分区表已经正确且希望保留 NVS、资源和历史数据的设备。写入地址必须与当前启动分区对应，不能把 App bin 写到 `0x0`。
- **Merged bin**：从 `0x0` 完整写入，包含 bootloader、分区表、OTA data 和 App。适合首次刷机或分区表升级，但可能覆盖分区布局；刷机前应确认是否需要备份配置和自定义资源。

`v1.5.x` 分区表与旧版不同。首次从 `v1.4.x` 升级时优先完整刷写。已经正确写入 `v1.5.x` 分区后，后续版本可以正常 OTA。

## 8. 上位机 DIY 图片资源

设备预留独立 `assets` 分区，支持上位机写入：

- 天气时钟 GIF 区域：固定尺寸和帧数的 1-bit 动画。
- 图片时钟图库：固定尺寸的 1-bit 图片，可按设备保存的 `30m / 1h / 6h / 12h / 24h` 周期轮换。
- 可选天气城市和自定义 OTA 地址等资源包配置。

用户资源会经过资源包头、尺寸、偏移、长度和 CRC 校验。资源不存在或损坏时，固件会回退到内置素材。

资源加载器的内部依赖和重复诊断声明已精简；内置星期图库和天气状态 GIF 的尺寸信息均与完整像素数据分开管理，减少固件构建时对大型生成资源的重复处理。天气状态 GIF 的差分像素也会先批量写入画布缓冲，再只刷新实际变化矩形，避免单个像素反复安排整张画布刷新。资源包格式、校验顺序、日志文字、图片/GIF 画面、帧率、星期映射、上位机接口和内置素材回退行为均保持不变。

注意：`v1.5.0` 调整过分区地址。旧上位机必须使用当前设备分区表或新版地址，不能继续按 `v1.4.x` 的固定地址写入。

## 9. 电池、充电与低电量

- 开机会立即采样一次电池。
- 未充电时，电池 ADC 与温湿度采样保持相同节奏：白天每分钟、夜间每两分钟。
- 温湿度采样完成后会通知当前页面按需更新；状态没有变化时不会反复刷新相同文本，约每分钟仅做一次容错复核。
- 确认充电后，无论充电图标动画是否已经停止，电池都会约每秒采样；检测到拔掉充电器后再恢复白天每分钟、夜间每两分钟的节奏。
- 已确认充电时，开机、OTA 操作结束或网络校时恢复不会把电池采样短暂降回普通分钟间隔；充电与拔电检测会继续保持原有快速响应。
- 低电量阈值、充电识别、动画停止和充电快速采样共用同一份内部策略；动画状态只控制可见闪烁，不再延迟拔电识别，电量显示、低电量行为和 OTA 保护保持不变。
- 每次电池采样完成后都会释放 ADC 与校准资源，不会在采样间隔内持续占用电池测量外设。
- 如果极少数情况下 ADC 通道配置和资源释放连续失败，设备会在后续采样中先恢复通道再读取，不需要用户重启；正常采样节奏和电量算法不变。
- 正式固件不会为每次电池采样输出 raw、电压和百分比明细；采样失败、开始充电、充电动画完成和拔掉充电器等关键状态仍会记录。采样速度、电量计算和页面显示不受影响。
- 电量、充电状态和低电量模式会作为同一次采样结果一致更新；页面、OTA 和小智读取电池信息时无需额外触发 ADC。
- 低电量时设备进入极简页面，停止非必要联网、动画、音频和高频刷新。
- 插上充电器并让电量恢复到退出阈值后，设备会回到进入低电量模式前的工作页；如果该页面已经关闭，则回到当前第一个启用页。恢复页只在本次开机的 RAM 中保存，不增加 NVS 写入；配网页仍在运行时会等配网结束后再恢复。
- 如果天气、每日文字或网络检测刚排队时进入低电量模式，设备会在打开 Wi-Fi 前取消这些请求；网络检测页面会显示“电量低，已跳过”。手动校时和进入配网仍保持原有操作。
- 如果低电量在网络检测运行途中出现，设备会让当前检测项安全结束后停止后续项目；已经完成的结果会保留，剩余项目显示“电量低，已跳过”。
- 充电状态基于电压趋势推断，电量百分比是估算值，不应作为精密电池仪表使用。

## 10. 恢复出厂设置与保留数据

恢复出厂设置会清除：

- 主、备 Wi-Fi 名称、密码和当前首选槽位。
- 和风天气 API 密钥与手动天气城市。
- 离线模式。
- 声音、音量、整点/全天提醒设置。
- 页面开关、页面顺序和小智节能（自动返回）设置。
- 单次闹钟。

恢复出厂设置会保留：

- 已绑定的小智账号/激活信息。
- 温湿历史分区中的已有记录。
- 上位机写入的 DIY 图片资源。

只有上述普通配置和单次闹钟都清理成功后，设备才会按未配网流程重新进入配网页。如果清理过程遇到存储异常，设备会提示失败并优先保留 Wi-Fi/API Key/API Host，方便再次执行恢复操作。

## 11. 常见问题

### 配网页没有自动弹出

确认手机仍连接 `WeatherClock-` 热点，并关闭会自动切换移动数据的功能，然后访问 `http://192.168.4.1/`。

启动页、设备配网状态和手机配网页显示的热点名称都来自当前正在使用的同一份完整名称；如果名称显示为空或不一致，请重新进入配网并保留串口日志。

如果配网页服务启动失败，设备会自动清理本次未完成的热点并恢复原 Wi-Fi 工作模式，不会持续保留一个不可用的高功耗热点。稍后重新进入配网即可。

如果设备正在结束其它联网工作，或热点因临时资源不足未能立即启动，进入配网的请求会继续排队并按有界间隔重试，不会高频反复启动 Wi-Fi。原有配网页、验证反馈和重新填写流程不变。

重复发布已经关闭的配网页状态不再被视为网络状态变化，因此启动失败不会自行提前唤醒下一次重试；真实的配网页关闭仍会立即唤醒结果交接和网络任务。

配网页已兼容常见手机浏览器较长的请求头。如果手机仍显示 `Header fields are too long` 或 `431`，请关闭系统自动弹出的页面，重新连接设备热点后手动访问 `http://192.168.4.1/`。该提示表示本次网页请求未进入保存处理，不代表 NVS、Wi-Fi 密码、天气 API Key 或 API Host 已损坏。

### 天气一直显示“等待数据”

检查 Wi-Fi、和风天气 API 密钥、账号专属 API Host 和天气城市。在 **设置 > 网络 > 同步天气** 手动同步，或进入 **系统 > 网络检测** 查看 QWeather、DNS 和公网状态。

自动同步遇到 Wi-Fi 启动失败、连接超时或配网天气配置验证失败时，会保留已有天气缓存并按既有有界重试/下次调度恢复，不会清除 Wi-Fi、API Key、API Host 或城市设置。配网验证失败会继续保留热点并显示具体原因，普通后台同步失败会释放本次网络资源；配网热点瞬时启停失败仍按原有有界间隔重试，网络状态变化时可提前继续处理。用户操作和重试节奏不变。若长时间仍无数据，再使用手动同步或网络检测定位。

联网失败收尾现在直接维护同一份后台同步运行状态，不再把天气、每日文字和 NTP 的跨轮字段拆开传递。这项内部整理不会改变联网时机、失败提示、退避、缓存、Wi-Fi 开关或用户操作。

冷启动期间如果内存暂时不足，后续天气请求会延后重试；已经完成的 IP 定位会短暂复用，不会每次重试都重新访问定位服务。该过程无需用户操作，成功、失败或切换手动城市后会自动清理临时信息。

界面因配网切换或显示资源恢复而重建时，天气城市、状态、图标和温湿度会重新写入新页面对象；已有缓存不会因为界面重建被清除。

天气时钟中的本地温湿度和趋势箭头也会在新页面对象上恢复；界面重建不会清除传感器样本或重新计算四小时趋势。

顶部日期、天气预警以及声音、Wi-Fi、闹钟图标会按照重建时的当前状态恢复；界面重建不会改变预警轮播或这些功能的启用状态。

主时间、秒数、状态动画、秒进度和低电量提示也会在界面重建后恢复，并继续按原来的分钟、秒和局部刷新规则运行。

### 手动城市不生效

建议填写常用城市名，例如“杭州”“上海”。设备支持“杭州市”等形式并会自动去掉末尾“市”。如果同名城市较多，和风天气返回的第一项可能不是预期地区，可恢复自动定位或改用更明确的城市名称。

### 图片或 GIF 写入后不显示

确认上位机使用当前分区表、WCA1 资源格式、正确尺寸和 CRC。无效资源会被固件安全忽略并回退内置素材。

### 小智提示服务不可用或准备时间较长

等待 Wi-Fi、模型和 Codec 初始化；主任务因瞬时资源不足启动失败时会约每 5 秒自动重试，无需反复切换页面。若长时间无法恢复，可切换到其他页面再重新进入，并通过串口日志检查网络、模型和音频初始化状态。
Wi-Fi 启动或连接超时后，设备会在约 15 秒后重试；等待期间会关闭本次失败会话占用的网络和语音资源，避免一直维持对话功耗。
麦克风偶发读取异常会自动短暂重试；若连续约 1 秒无法恢复，设备会退出异常采集循环并自动重建语音监听，无需持续停留在高频错误状态。
异常监听任务停止时，固件也会统一释放本轮录音缓冲，反复自动恢复不会持续占用更多 PSRAM。
小智工具响应在瞬时内存不足时会安全放弃本次构造并释放临时数据；若某次设置或查询没有完成，可等待服务恢复后重新说一次，不需要重启设备。
如果扬声器写入异常，设备会立即结束本轮语音会话、释放尚未播放的数据并自动恢复监听，不再长时间停留在“正在说话”。
通过小智修改天气城市后，设备会在释放实时语音资源后更新全部天气；若网络异常导致刷新迟迟未完成，小智不会永久停留在等待状态，天气请求会继续由后台处理。

### OTA 检测不到刚发布的版本

先确认设备可访问 GitHub OTA 主清单。Gitee OTA 备用源也由源码构建完成事件触发同步；若自动构建或镜像仍在运行，短时间内可能暂时保留上一版。

如果串口日志同时显示 `OTA manifest source skipped: GitHub` 和 `OTA manifest source skipped: Gitee`，说明当前固件构建时没有注入生产 OTA 地址，设备实际上没有发起 HTTP 请求。这不是 Wi-Fi 或 JSON 长度问题。该版本不能依靠内置 OTA 自行恢复，需要先通过串口刷入修正后的 App 固件（可保留 NVS），或由上位机写入有效的自定义 OTA 地址。

### 时间丢失后开机显示不完整

RTC 时间不可信时，设备会先显示占位并尝试 NTP；本地温湿度无缓存时会立即采样。首次 NTP 失败后约 15 秒重试，设置页手动同步不等待自动退避；同步成功会立即刷新日期、星期和时间，随后天气与每日文字继续按错峰计划补齐。若串口持续出现 `task_wdt` 且指出 `network_sync`，属于异常忙循环而不是正常等待，应保留日志并升级固件。

关于本机显示的最近同步时间与网络任务写入使用同一份任务互斥快照；同步等待、RTC 回写和页面通知仍在锁外执行，因此查看该信息不会延长联网等待或影响时间同步结果。

闹钟、番茄钟、最近 NTP 同步时间、关于本机、每日文字、手动天气城市、联网凭据、网络检测、完整天气数据和小智待保存天气城市运行态在内部复用同一套应用期静态 mutex 所有权工具，减少重复初始化代码；倒计时、闹钟时间、同步、配网、天气更新、网络检测、页面超时、内存分配和用户操作均不改变，需要显式回滚的资源仍保留原生命周期。

### 开机画面未继续显示

若极少见的显示资源或面板寄存器启动错误导致开机停止，固件会释放已经取得的 SPI bus、panel 接口、RESET GPIO、显示缓冲、查找表、LVGL 缓冲、定时器和锁，不会反复重启或在不可用状态下持续周期唤醒。维护门禁还会检查每块显示缓冲只释放一次、同一初始故障只记录一次错误，降低后续代码调整引入堆损坏或重复诊断的风险。RLCD 生命周期与传输诊断改为复用同一模块标签，不再让唯一显示对象保存无必要的指针；正常日志内容和回滚行为不变。LVGL 常驻显示锁、handler task 栈和任务控制块使用静态存储，减少冷启动内部堆分配和长期碎片，页面、按键和刷新行为不变。重新上电后若仍无法进入工作页，请查看串口中的 `RLCD display resources unavailable`、`RLCD panel register initialization failed`、`LVGL initialization failed` 及其前一条具体错误。

启动动画会先把每一帧完整写入画布缓冲，再统一请求一次显示刷新，避免逐像素重复安排重绘。动画结束并进入工作页后，固件会释放只供动画使用的约 25 KiB PSRAM 画布，为后续天气联网、页面绘制和音频保留更多启动 CPU 与内存余量；启动画面、帧间隔、停留时间和页面切换效果不变，用户无需操作。

若共享 I2C master bus 本身无法创建，固件会在 RTC、传感器、音频、网络和应用任务初始化前停止启动，不会进入复位循环。请重新上电并查看串口中的 `I2C master bus unavailable` 及其前一条驱动错误。单独缺少 RTC 或温湿度传感器仍属于可恢复的设备级错误，本身不会阻止时钟运行。

启动时若检测到上位机写入的自定义资源包，固件仍会执行包头和完整 payload CRC 校验。额外的四帧图片密度诊断只在 DEBUG 日志开启时运行，并继续使用固定小块读取；普通启动、资源格式、显示效果和损坏时回退到内置素材的规则不变。

自定义资源目录只会在工作任务启动前加载一次，之后页面、天气城市和 OTA 配置只读取已经校验的目录。该维护不会改变 WCA1 格式、资源优先级、内置回退或上位机使用方式。

正常运行中若 SPI 显示传输遇到短暂内存不足或超时，设备会有限重试；仍失败时只跳过这一帧并记录 `RLCD command/data tx failed`，不会因此自动重启。联网和 OTA 的显示 DMA 保护状态使用无分配的原子快照，页面刷新读取保护档位时不会关闭跨核中断；分块大小、重试次数和画面效果保持不变。若同类日志持续出现，请检查供电和串口中的 DMA 余量。

显示驱动的像素查找表现在按实际屏幕高度计算，并会在启动前拒绝无法安全表示的异常屏幕尺寸，避免维护或方向调整后出现错行、越界或花屏。当前设备的 400×300 画面、PSRAM 占用、页面布局和刷新方式不变，无需调整任何设置。

公共位图、标签和字体声明使用更轻量的内部接口；这项维护不会改变中文字形、图标像素、页面坐标、趋势箭头或局部刷新行为。

天气时钟与温湿时钟使用的数码字体现在共享同一份只读位图，减少约 5 KiB 的重复固件数据。天气时钟数字也改为一次批量写入画布缓冲后再执行原有最终刷新，减少秒级重复显示调度；数字字形、大小、位置和刷新时机保持不变。

电池、预警、声音、Wi-Fi、闹钟、趋势和温湿度图标也由各页面共享同一份只读资源，进一步减少重复固件数据。1-bit 图标像素改为一次批量写入画布缓冲后再执行一次最终刷新，减少重复显示调度；图标像素、线条粗细、位置、显示条件和更新时间保持不变。

设备内部的画布缓冲、基础配置和局部刷新接口也由同一轻量模块统一维护。全天进度、温湿历史曲线、设置页 OTA 进度和状态动画仍使用原有像素、坐标和刷新时机，用户不需要改变任何设置或操作。

启动画面和启动联网进度也使用独立的内部接口，闹钟、番茄钟、每日文字、天气城市、配网和小智服务通过统一的轻量通知入口刷新界面。这项维护不改变开机预算、Wi-Fi/NTP 顺序、声音提醒、页面返回、配网反馈或任何用户操作。

温湿历史、OTA、联网同步和 Wi-Fi 射频控制也已改用各自需要的内部接口，不再加载无关的整套界面声明。Wi-Fi 射频状态对普通模块保持只读，只有底层驱动所有者能在真实启停成功后发布状态，避免其它功能误报状态栏图标或影响低功耗收尾。这项内部维护不改变传感器采样、固件升级、联网时序、配网方式、页面显示或按键操作。

项目维护流水线现在会自动记录每项优化处于待验证、已验证、待同步或已同步状态，减少人工记录与实际 Gitea 状态不一致的情况。这项改动只影响开发维护流程，不改变设备功能、版本号或升级方式。

每日文字的后台缓存检查只读取是否可用和最近同步时间，只有图片时钟实际需要显示时才复制完整文字。这项内部优化不改变每日文字内容、当天缓存、跨日更新、手动更新或页面显示方式。

每日文字完整内容的读取和更新也减少了内部临时复制，降低图片时钟刷新与联网更新时的瞬时任务栈占用；文字内容、截断、更新时间和操作方式保持不变。

设备内部的工作页目录现在会在编译时拒绝未登记的页面能力标记，降低以后新增页面时绕过联网或低刷新规则的风险。当前页面、设置、同步、显示和操作方式均未改变，用户无需进行任何调整。

设备内部的常驻任务目录现在会在编译时拒绝重复任务函数或名称，并要求只有一个 UI 通知句柄所有者，降低以后维护时误启动两份联网、采样、闹钟或番茄钟任务的风险。当前任务、时序、页面、功耗行为和操作方式均未改变。

设备尚未配置 Wi-Fi 时，天气和每日文字页面不再排队必然无法完成的自动联网请求；完成配网后，缺失或过期数据仍按原有退避规则补拉。页面内容、配网步骤、同步行为和操作方式均未改变。

本地温湿度读取现在统一复用同一份内部一致快照。采样间隔、四小时趋势、页面数值、小智温湿度查询、刷新时机和操作方式均未改变。

图片时钟读取每日文字时，现在会同时取得正文、同步时间和对应版本；若设备短暂忙碌导致本次读取失败，页面会在下一轮继续尝试，不会一直留空到下次联网更新。每日文字内容、获取时机、跨日刷新、页面显示和操作方式均未改变。

天气时钟和天气看板现在只会在完整天气快照读取成功后更新内容。若内部读取未完成，页面会继续保留上一份有效天气并在后续重试，不会用空数据覆盖现有显示；天气服务、刷新时机、布局、占位和操作方式均未改变。

电池状态在内部快照短暂不可用时会继续保留上一份有效数据，不再误显示默认电量。正常采样间隔、充电动画、低电量保护、关于本机、OTA 和操作方式均未改变。

设备启动异常导致首次电池状态暂时不可读取时，工作页会使用确定的安全兜底并继续重试，不会使用未初始化数据误切换低电量页面或充电显示。正常启动、采样和页面行为不变。

天气缓存时间等元数据在内部短暂不可用时也会保留上一份有效值；关于本机不会再把已有的上次天气同步时间误显示为占位符。天气内容、更新时间、联网、布局和操作方式均未改变。

网络检测页现在只会在取得完整内部快照后更新摘要和结果行。设备短暂忙碌时会保留上一帧已显示结果，不再回退为占位符；检测项目、超时、联网、布局和操作方式均未改变。

关于本机页在内部页面状态短暂不可用时会继续保持显示，不再意外返回工作页；正常自动返回时机、按键、OTA 状态、布局和操作方式均未改变。

设置页反馈在内部状态短暂不可用时会继续保留，不会在正常到期前意外消失；同步、保存和确认提示、设置页时序、布局及操作方式均未改变。

若极少见的按键中断或 Light Sleep 唤醒初始化失败，设备会降低异常回退路径的空闲轮询频率：设置、配网等交互页保持 50ms，普通工作页为 250ms，分钟级页面为 500ms，按住按键后仍使用 20ms 跟踪。正常设备继续由 GPIO 边沿即时唤醒，因此防抖、短按、长按、页面操作、显示刷新和正常 Light Sleep 行为均未改变。

启动联网、天气同步、OTA 或切换离线模式结束后，设备现在通过同一内部入口复核 Wi-Fi 是否仍开启，并仅在需要时登记后续关闭。射频关闭顺序、联网内容、重试、页面显示和用户操作均未改变；这项维护用于降低未来新增失败路径遗漏关网收尾的风险。

显示底层现在会在每轮整屏或局部像素发送完成后确认 SPI 队列已经清空，再允许下一轮刷新改写同一缓冲；发送异常时也会先完成已排队事务的收尾。页面内容、局部刷新范围、刷新频率和操作方式均未改变，用于降低快速连续刷新或联网内存压力期间偶发花屏的风险。

网络检测现在会在天气或每日文字检查结束后立即显示该项结果，再开始 NTP 或公网检查，不再让已完成项目长时间停留在“检测中”。九项检测内容、顺序、请求次数、超时、Wi-Fi 使用和操作方式均未改变。

网络检测现在会分别判断公网 IP 服务是否成功响应、以及响应内容能否解析为合法 IPv4。若服务已成功响应但返回格式暂时不兼容，公网 IP 行仍显示失败，公网连通性则直接判定可达，不再为同一地址重复建立一次 HTTPS；真正的网络请求失败仍会执行原有兜底探测。
